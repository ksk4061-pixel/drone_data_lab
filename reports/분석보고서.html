3데이터 처리 기준과 근거

항목건수처리근거
downtime_hours = 9994결측(NaN)으로 바꿈. 평균 · 중앙값으로 채우지 않음미입력 표시값. 평균으로 채우면 값을 지어내게 됨. 모델(LightGBM)이 결측을 처리
maintenance_cost > 1,0005100으로 나눔. 나눈 행은 cost_fixed=1로 표시자릿수 입력 오류. 나눈 값이 사후정비 정상 범위에 듦
fault_category · fault_code 결측2,645"N/A" 범주로 채움전부 예방정비(고장 없음). 최빈값으로 채우면 없는 고장 유형이 생김. fault_code(40종)는 모델에 쓰지 않음
days_since_last_maintenance 결측150비워 두고 is_first_maintenance(1/0) 열 추가드론별 첫 정비. 0으로 채우면 방금 정비한 것처럼 보임
  • 행을 지우지 않음. 처리 전 3,693건 → 처리 후 3,693건(학습 2,346 + 시험 1,241 + 이번 달 106). 건수 대조: AGENTS.md의 처리 기준과 일치 = True
  • 처리 뒤 downtime_hours 최댓값 74.0, maintenance_cost 최댓값 611
  • 출처: python scripts/eda.py (drone_lib.clean)

4만든 피처와 넣지 않은 컬럼

같은 드론의 그 정비일까지의 기록만 사용함(같은 날짜 포함, 이후 기록은 사용하지 않음). 시험 · 이번 달 피처는 학습 → 시험 → 이번 달 기록을 이어서 계산함.

피처정의
최근 30 · 90 · 365일 고장 수그 정비일 기준 최근 30 · 90 · 365일의 사후 · 긴급정비 수(이번 정비 포함)
직전 고장 뒤 경과일직전 사후 · 긴급정비로부터 경과일 (고장 이력이 없으면 비움)
예방정비 뒤 비행시간마지막 예방정비 이후 누적 비행시간 증가분
직전 정비 뒤 비행시간직전 정비 이후 누적 비행시간 증가분 (첫 정비는 비움)

최종 피처 18개: 드론 유형, 정비 구분, 고장 유형, 경과연수, 고장 심각도, 운용중단 시간, 수리 시간, 교체 부품 수, 정비 비용, 정비 성공 여부, 직전 정비 뒤 경과일, 첫 정비 여부, 최근 30일 고장 수, 최근 90일 고장 수, 최근 365일 고장 수, 직전 고장 뒤 경과일, 예방정비 뒤 비행시간, 직전 정비 뒤 비행시간

6위험 표시 기준

  • 검증 기간에서 ‘놓친 재고장 수 × 300 + 기준 이상 건수 × 60’(만원)이 가장 작은 확률 기준을 고름. 시험 데이터(2025)로 고르지 않음
놓친 재고장 비용고른 기준기준 이상 건수놓친 재고장총 비용(만원)
300만원 (선택)0.242392923,040
600만원 (비교)0.103681229,280
  • 비용을 300 → 600만원으로 올리면 기준이 0.24 → 0.10로 내려가고, 기준 이상이 239 → 368건으로 늘며 놓친 재고장은 29 → 12건으로 줆. 놓치는 비용이 클수록 더 많이 점검하는 쪽으로 기준이 움직임
  • 비교 정책(검증 643건 중 재고장 176건): 아무도 점검하지 않으면 300만원 기준 52,800만원, 전부 점검하면 38,580만원, 기준 0.24로 고르면 23,040만원
  • 출처: python scripts/train.py → artifacts/threshold_cost.csv, artifacts/model_card.json

7시험 기간 예측 제출

  • reports/test_predictions_2025.csv: drone_test.csv 1,241건 모두에 재고장 확률을 매김(열: equipment_id, maintenance_date, prob). 확률 평균 0.261, 범위 0.025 ~ 0.957
  • 시험용 모델은 정비일 ≤ 2024-12-01 행으로 학습함. 시험 피처는 학습 기록과 이어서 계산함
  • 시험(2025) 정답은 없으므로 시험 기간 PR-AUC · 적중 수는 계산하지 못함. 정답을 기록에서 다시 만들지 않았음. 위 성능은 검증 기간 값이며, 시험 성능은 제출한 확률로 강사가 채점함
  • 출처: python scripts/train.py

8모델의 한계 (artifacts/model_card.json의 limits)

  • 교육용 가상 데이터로 학습했다. 실제 드론에 그대로 쓰지 않는다.
  • 확률은 '정비 뒤 30일' 기준이다. 정비 기록이 없는 드론은 판단하지 않는다.
  • 시험(2025) 정답이 없어 시험 성능은 계산하지 못했다. 성능은 검증 기간(2024-07 ~ 12) 기준이다.
  • 검증 기간 점검(B3)에서 '최근 정비가 사후 · 긴급정비인 드론부터 고르는' 단순 규칙이 월 20대 적중에서 모델과 비슷하거나 약간 더 많이 맞혔다. 모델의 가치는 재고장 확률(위험 표시 기준 · 비용 계산)이며, 상위 20대 선정만으로 단순 규칙보다 낫다고 말할 수 없다.
  • 최종 판단은 정비 담당자가 한다. 모델은 점검 순서를 정하는 참고 자료다.
